# 要求仕様書

## 概要
本ドキュメントは、支払履歴登録API機能の要求仕様を定義します。この機能により、ユーザーは自身のサブスクリプションに対する支払履歴をシステムに登録できるようになります。

## 要求事項

### 要求事項1：支払履歴登録APIエンドポイント
**目的：** 認証されたユーザーとして、新しい支払履歴を登録するためのAPIエンドポイントを提供する。
**トリガー：** ユーザーが支払履歴登録APIにPOSTリクエストを送信する。

#### 受け入れ基準
1.  **WHEN** 認証されたユーザーが必須項目（サブスクリプションID、支払日、金額、通貨、支払方法）を含む有効なデータで支払履歴登録エンドポイント（`/api/v1/payments`）にPOSTリクエストを送信した場合、**THEN** システムはステータスコード201（Created）と共に、登録された支払履歴の情報を返さなければならない。
2.  **IF** リクエストに必須項目が不足している場合、**THEN** システムはステータスコード400（Bad Request）とエラーメッセージを返さなければならない。
3.  **IF** リクエスト内のデータ型が無効である場合（例：金額が数値でない）、**THEN** システムはステータスコード400（Bad Request）とエラーメッセージを返さなければならない。
4.  **IF** 指定された`subscription_id`が存在しない場合、**THEN** システムはステータスコード404（Not Found）を返さなければならない。
5.  **IF** 指定された`subscription_id`が、認証されたユーザーのものではない場合、**THEN** システムはステータスコード403（Forbidden）を返さなければならない。
6.  **IF** リクエストヘッダーに有効なJWTアクセストークンが含まれていない場合、**THEN** システムはステータスコード401（Unauthorized）を返さなければならない。

### 要求事項2：支払履歴データの保存
**目的：** API経由で受け取った有効な支払履歴データをデータベースに永続化する。

#### 受け入れ基準
1.  **WHEN** 有効な支払履歴データを受け取った場合、**THEN** システムは`payment_histories`テーブルに新しいレコードを作成しなければならない。
2.  **WHEN** 新しいレコードが作成される際、**THEN** システムはリクエストから受け取った`subscription_id`, `payment_date`, `amount`, `currency`, `payment_method`を保存しなければならない。
3.  **WHEN** 新しいレコードが作成される際、**THEN** システムはリクエスト元のユーザーIDを`user_id`として保存しなければならない。
4.  **WHEN** 新しいレコードが作成される際、**THEN** システムは指定された`subscription_id`に対応するサブスクリプション名を`subscription_name`として保存しなければならない。

### 要求事項3：為替レートの自動計算と保存
**目的：** 支払通貨がユーザーの基本通貨と異なる場合、自動的に為替レートを取得し、換算後の金額を計算して保存する。

#### 受け入れ基準
1.  **IF** 支払通貨（`currency`）がユーザーの基本通貨（`users.base_currency`）と異なる場合、**THEN** システムは基本通貨に合わせずに、支払通貨のまま保存する。
2.  **WHEN** 為替レートが正常に取得できた場合、**THEN** システムはそのレートを`payment_histories`テーブルのrate関連の列 (`rate_from_currency`, `rate_to_currency`, `currency`, `rate_date`) に保存しなければならない。
3.  **IF** 支払通貨とユーザーの基本通貨が同じである場合、**THEN** システムは`exchange_rate`を`1.0`、`converted_amount`を元の`amount`と同じ値として保存しなければならない。
4.  **IF** 該当する為替レートが見つからない場合、**THEN** システムはステータスコード400（Bad Request）とエラーメッセージ（例：「指定された日付の為替レートが見つかりません」）を返さなければならない。
