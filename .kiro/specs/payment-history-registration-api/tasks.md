# 実装タスクリスト: 支払履歴登録API (TDDアプローチ)

## 概要
このタスクリストは、テスト駆動開発（TDD）のアプローチに基づき、「支払履歴登録API」を実装するための具体的な作業項目を定義します。レッド・グリーン・リファクタリングのサイクルを意識した順序で構成されています。

---

### 1. 準備: 最初のテストのセットアップ
**目的**: 最も単純な正常系（ハッピーパス）のテストを書くための準備を整える。
- [x] **1.1.** `POST /api/v1/payments` に対する結合テスト用のファイルと基本的なセットアップ（テストクライアントの準備など）を行う。
- [x] **1.2.** 支払い通貨がユーザーの基本通貨と同じである場合の、支払い履歴登録（`201 Created`）を期待する、失敗する結合テスト（レッドフェーズ）を1つ記述する。

### 2. 機能実装: 基本的な支払い履歴の登録
**目的**: 最初のテストをパスさせ（グリーンフェーズ）、最もシンプルな支払い登録機能を実装する。
- [x] **2.1.** `app/api/v1/payment_history.py` に `POST /api/v1/payments` のエンドポイントと、リクエストを受け取るための最小限の関数 `create_payment` を作成する。(要件: 1.6)
- [x] **2.2.** `app/services/payment_history_service.py` に `create_payment` メソッドを作成する。この段階では、通貨換算を行わない単純な登録処理のみを実装する。(要件: 2.1, 2.2, 2.3, 2.4, 3.3)
- [x] **2.3.** API層とサービス層を連携させ、タスク1.2のテストをパスさせる。

### 3. リファクタリング: 依存関係の改善
**目的**: テストが通る状態を維持しつつ、コードの内部品質を向上させる（リファクタリングフェーズ）。
- [x] **3.1.** `PaymentHistoryService` のコンストラクタを修正し、依存コンポーネント（リポジトリ群、サービス）が外部から注入されるように変更する（DIの徹底）。
- [x] **3.2.** 関連するテストコードを修正し、すべてのテストがパスすることを確認する。

### 4. 機能拡張: 為替レートの取り扱い
**目的**: 新たなテストを追加し、為替レートの取得・保存機能を段階的に実装する。
- [x] **4.1.** 支払い通貨がユーザーの基本通貨と異なる場合の登録を期待する、新しい失敗する結合テスト（レッドフェーズ）を追加する。(要件: 3.1, 3.2)
- [x] **4.2.** `PaymentHistoryService.create_payment` メソッドを拡張し、`ExchangeRateService` を呼び出して為替レート情報を取得・保存するロジックを追加する。
- [x] **4.3.** タスク4.1のテストをパスさせる（グリーンフェーズ）。その後、コード全体をリファクタリングする。

### 5. 機能実装: 主要なエラーハンドリング
**目的**: 想定される異常系の振る舞いをテストで定義し、エラーハンドリングを実装する。
- [x] **5.1.** 不正なリクエストボディ（必須項目不足など）に対して `400 Bad Request` が返ることを期待する、失敗するテストを追加する。(要件: 1.2, 1.3)
- [x] **5.2.** API層にリクエストバリデーションのロジックを追加し、テストをパスさせる。
- [x] **5.3.** 存在しない、または権限のない `subscription_id` を指定した場合に `404 Not Found` / `403 Forbidden` が返ることを期待する、失敗するテストを追加する。(要件: 1.4, 1.5)
- [x] **5.4.** サービス層にサブスクリプションの存在確認と所有権チェックのロジックを追加し、テストをパスさせる。
- [x] **5.5.** 該当する為替レートが見つからない場合に `400 Bad Request` が返ることを期待する、失敗するテストを追加する。(要件: 3.4)
- [x] **5.6.** サービス層に為替レート取得失敗時のエラーハンドリングロジックを追加し、テストをパスさせる。

### 6. 仕上げ: 単体テストと最終リファクタリング
**目的**: 機能全体の品質を保証するため、より詳細な単体テストを整備し、コードをクリーンアップする。
- [x] **6.1.** `PaymentHistoryService` のロジック（特に分岐処理）を網羅する単体テストを整備し、品質を保証する。
- [x] **6.2.** 機能全体の実装を見直し、命名の改善や重複コードの排除などのリファクタリングを行う。
