# 実装タスク一覧

## タスク概要

本タスクはt-wadaのTDD（テスト駆動開発）アプローチに従う。「テストファースト」の原則で、各機能について「レッド → グリーン → リファクター」のサイクルを回す。

**TDDサイクル**:
1. **レッド**: まずテストを書き、失敗させる
2. **グリーン**: テストを通すための最小限の実装を行う
3. **リファクター**: コードを整理・改善する

---

## タスク

### Phase 1: Service層のTDDサイクル

- [x] 1. Service層のユニットテストを作成する（レッド）
- [x] 1.1 change_passwordメソッドのテストケースを作成する
  - 正常なパスワード変更が成功することを検証するテストを書く
  - 現在のパスワードが正しくない場合にInvalidPasswordErrorが送出されることを検証するテストを書く
  - 新しいパスワードが8文字未満の場合にValueErrorが送出されることを検証するテストを書く
  - ユーザーが存在しない場合にUserNotFoundErrorが送出されることを検証するテストを書く
  - 新しいパスワードが正しくハッシュ化されて保存されることを検証するテストを書く
  - テストを実行し、すべて失敗することを確認する
  - _Requirements: 1.1, 1.3, 2.2, 3.2, 3.5_

- [x] 2. Service層にパスワード変更機能を実装する（グリーン）
- [x] 2.1 UserServiceにchange_passwordメソッドを追加する
  - ユーザーIDでユーザーを取得し、存在しない場合はUserNotFoundErrorを送出する
  - 現在のパスワードを検証し、不正な場合はInvalidPasswordErrorを送出する
  - 新しいパスワードが8文字以上であることを検証し、短い場合はValueErrorを送出する
  - 新しいパスワードをハッシュ化して保存する
  - 成功時はINFOレベル、失敗時はWARNINGレベルでログを記録する（パスワードは除外）
  - テストを実行し、すべて成功することを確認する
  - _Requirements: 1.1, 1.3, 2.2, 3.2, 3.4, 3.5, 8.1, 8.2, 8.3_

### Phase 2: API層のTDDサイクル

- [x] 3. API層の統合テストを作成する（レッド）
- [x] 3.1 POST /api/v1/users/{userId}/change-passwordエンドポイントのテストを作成する
  - 有効なJWTトークンでパスワード変更が成功することを検証するテストを書く
  - JWTトークンなしでアクセスした場合に401が返されることを検証するテストを書く
  - 他のユーザーのパスワードを変更しようとした場合に403が返されることを検証するテストを書く
  - 無効なリクエストボディで400が返されることを検証するテストを書く
  - データベースでパスワードが正しく更新されることを検証するテストを書く
  - テストを実行し、すべて失敗することを確認する
  - _Requirements: 1.2, 2.1, 2.3, 3.1, 3.3, 4.1, 4.2, 4.3, 5.1, 5.2, 5.3, 6.1, 6.2, 6.3_

- [x] 4. API層にパスワード変更エンドポイントを実装する（グリーン）
- [x] 4.1 POST /api/v1/users/{userId}/change-passwordエンドポイントを追加する
  - JWT認証を要求し、トークンがない場合は401 Unauthorizedを返す
  - パスパラメータのユーザーIDとJWTのユーザーIDが一致しない場合は403 Forbiddenを返す
  - リクエストボディからcurrent_passwordとnew_passwordを取得する
  - 必須フィールドが不足している場合は400 Bad Requestを返す
  - UserService.change_passwordを呼び出し、成功時は200 OKと成功メッセージを返す
  - 各例外に応じて適切なエラーレスポンス（400, 404, 500）を返す
  - success_responseユーティリティを使用して一貫したレスポンス形式を提供する
  - テストを実行し、すべて成功することを確認する
  - _Requirements: 1.2, 2.1, 2.3, 3.1, 3.3, 4.1, 4.2, 4.3, 5.1, 5.2, 5.3, 6.1, 6.2, 6.3, 6.4, 7.1, 7.2, 7.3_

## TDD実行のポイント

1. **小さく始める**: 一度に1つのテストケースを書き、失敗を確認してから実装する
2. **コミット頻度**: 「レッド → グリーン」のサイクルごとにコミットする
3. **リファクター**: テストが通った後に、コードの整理を行う
