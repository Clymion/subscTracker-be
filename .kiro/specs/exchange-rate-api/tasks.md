# 実装計画: 為替レートAPI

- [x] 1. データアクセス層の実装
- [x] 1.1 為替レートを取得するためのデータアクセスロジックを実装する
  - データベースクエリを担当するコンポーネントを作成する。
  - 指定された日付と通貨ペアに一致するレートを検索するクエリを実装する。
  - 正確な日付にレートが存在しない場合、その日付以前で最も新しいレートを返すフォールバックロジックを実装する。
  - どの期間にもレートが見つからないケースを処理する。
  - _Requirements: 1.1, 1.2, 1.3_

- [x] 1.2 データアクセスロジックの単体テストを作成する
  - 指定日にレートが存在するシナリオをテストする。
  - 直近の過去のレートが返されるフォールバックシナリオをテストする。
  - レートが見つからず、null/Noneが返されるシナリオをテストする。
  - _Requirements: 1.1, 1.2, 1.3_

- [x] 2. ビジネスロジック層の実装
- [x] 2.1 為替レート取得のビジネスロジックを実装する
  - レート取得処理を調整するサービスクラスを作成する。
  - データアクセス層を呼び出してレートデータを取得する。
  - データ層からレートが返されない場合に「見つからない」状態を通知する準備をする。
  - _Requirements: 1.1, 1.3_

- [x] 2.2 ビジネスロジックの単体テストを作成する
  - リポジトリがデータを返した際に、サービスが正しくデータを返すことをテストする。
  - リポジトリがnull/Noneを返した際に、サービスが「見つからない」ことを示す特定の例外を発生させることをテストする。
  - _Requirements: 1.1, 1.3_

- [x] 3. API層の実装
- [x] 3.1 公開APIエンドポイントを実装する
  - GETリクエストを処理するAPIエンドポイントを作成する。
  - `date`, `from_currency`, `to_currency` のリクエストパラメータの解析を実装する。
  - パラメータが欠落している、または形式が不正な場合に「不正なリクエスト」を通知する処理を実装する。
  - `date` パラメータが省略された場合に現在の日付を使用するロジックを実装する。
  - エンドポイントをビジネスロジックサービスに接続する。
  - 成功時のレスポンスを正しくフォーマットする。
  - サービスレベルの例外を適切なHTTPエラーレスポンスに変換する（例：「見つからない」→ 404）。
  - _Requirements: 1.1, 1.3, 1.4, 1.5, 1.6_

- [x] 3.2 新しいAPIエンドポイントを登録する
  - 新しいエンドポイントをメインアプリケーションに統合し、検出可能かつアクセス可能にする。
  - _Requirements: 1.1_

- [x] 4. 統合テスト
- [x] 4.1 APIエンドポイントの統合テストを作成する
  - 成功するAPI呼び出しをシミュレートし、200 OKレスポンスと正しいレートデータを確認するテストを作成する。
  - 不正なパラメータ（欠落、不正形式）に対する400 Bad Requestレスポンスを確認するテストを作成する。
  - 利用可能なレートがない通貨ペア/日付に対する404 Not Foundレスポンスを確認するテストを作成する。
  - `date` パラメータを省略した場合に、現在日（または直近）のレートが返されることを確認するテストを作成する。
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 1.6_
