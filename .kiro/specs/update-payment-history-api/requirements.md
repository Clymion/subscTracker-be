# 要求仕様書

## 概要
本ドキュメントは、支払履歴更新API機能の要求仕様を定義します。この機能により、ユーザーは既存の支払履歴レコードの誤りを修正したり、不足している情報を追加したりできるようになります。

## 要求事項

### 要求事項1：支払履歴更新APIエンドポイント
**目的：** 認証されたユーザーとして、既存の支払履歴を更新するためのAPIエンドポイントを提供する。
**トリガー：** ユーザーが支払履歴更新APIにPATCHリクエストを送信する。

#### 受け入れ基準
1.  **WHEN** 認証されたユーザーが有効なデータで支払履歴更新エンドポイント（`/api/v1/payments/{payment_id}`）にPATCHリクエストを送信した場合、**THEN** システムはステータスコード200（OK）と共に、更新された支払履歴の情報を返さなければならない。
2.  **IF** リクエストに更新可能なフィールド（`subscription_id`, `payment_date`, `amount`, `currency`, `payment_method`）の一部のみが含まれている場合、**THEN** システムは提供されたフィールドのみを更新しなければならない（部分更新）。
3.  **IF** リクエスト内のデータ型が無効である場合（例：金額が数値でない、日付形式が不正）、**THEN** システムはステータスコード400（Bad Request）とエラーメッセージを返さなければならない。
4.  **IF** 指定された`payment_id`が存在しない場合、**THEN** システムはステータスコード404（Not Found）を返さなければならない。
5.  **IF** 指定された`payment_id`のレコードが、認証されたユーザーのものではない場合、**THEN** システムはステータスコード403（Forbidden）または404（Not Found）を返さなければならない（セキュリティ上の理由で存在を隠す場合は404）。
6.  **IF** リクエストヘッダーに有効なJWTアクセストークンが含まれていない場合、**THEN** システムはステータスコード401（Unauthorized）を返さなければならない。

### 要求事項2：支払履歴データの更新
**目的：** API経由で受け取った有効な支払履歴データでデータベースのレコードを更新する。

#### 受け入れ基準
1.  **WHEN** 有効な更新リクエストを受け取った場合、**THEN** システムは`payment_histories`テーブルの該当レコードを更新しなければならない。
2.  **WHEN** レコードが更新される際、**THEN** システムはリクエストから提供された`payment_date`, `amount`, `currency`, `payment_method`を更新しなければならない。
3.  **IF** `subscription_id`が変更された場合、**THEN** システムは新しい`subscription_id`に対応するサブスクリプション名を`subscription_name`として更新しなければならない。
4.  **IF** 更新後の金額が負の値である場合、**THEN** システムはステータスコード400（Bad Request）を返さなければならない。
5.  **IF** 更新後の通貨コードがサポートされていない場合、**THEN** システムはステータスコード400（Bad Request）を返さなければならない。

### 要求事項3：為替レートの再計算と更新
**目的：** 支払日または通貨が変更された場合、為替レートを再取得し、換算後の金額を再計算して保存する。

#### 受け入れ基準
1.  **IF** 支払通貨（`currency`）または支払日（`payment_date`）が更新された場合、**THEN** システムは新しい条件に基づいて為替レートを再取得しなければならない。
2.  **WHEN** 為替レートが再取得できた場合、**THEN** システムはそのレートで`rate_from_currency`, `rate_to_currency`, `rate_date`, `exchange_rate`を更新し、`converted_amount`を再計算して更新しなければならない。
3.  **IF** 支払通貨とユーザーの基本通貨が同じになるように更新された場合、**THEN** システムは`exchange_rate`を`1.0`、`converted_amount`を`amount`と同じ値に更新しなければならない。
4.  **IF** 該当する為替レートが見つからない場合、**THEN** システムはステータスコード400（Bad Request）とエラーメッセージ（例：「指定された日付の為替レートが見つかりません」）を返さなければならない。
