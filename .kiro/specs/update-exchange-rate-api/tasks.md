# 実装計画: 為替レートAPIの機能拡張

- [x] 1. データアクセス層の機能拡張
- [x] 1.1 基準通貨に基づいたレート取得機能の実装
  - 指定された日付以前で最新の、基準通貨に一致するすべての為替レートを取得するデータベースクエリを実装します。
  - _Requirements: 1.3_

- [x] 1.2 ユニットテストの作成
  - 上記で実装したリポジトリメソッドが、正しいデータを返すことを検証するユニットテストを作成します。
  - _Requirements: 1.3_

- [x] 2. サービス層のビジネスロジック実装
- [x] 2.1 複数レート取得サービスの開発
  - データアクセス層の新しいメソッドを呼び出し、為替レートのリストを取得します。
  - 取得したレートリストを、通貨コードをキーとする辞書形式に変換します。
  - _Requirements: 1.1, 1.2, 1.3_

- [x] 2.2 対象通貨によるフィルタリング機能
  - `target_currencies` パラメータが指定された場合、そのリストに含まれる通貨のレートのみを返すようにフィルタリングするロジックを実装します。
  - _Requirements: 1.4_

- [x] 2.3 データ不在時のエラーハンドリング
  - データベースからレートが見つからなかった場合に、`ResourceNotFoundError` 例外を送出する処理を実装します。
  - _Requirements: 1.7_

- [x] 2.4 サービス層のユニットテスト作成
  - フィルタリング機能やエラーハンドリングが正しく動作することを検証するユニットテストを作成します。
  - _Requirements: 1.4, 1.7_

- [x] 3. APIエンドポイントのリファクタリング
- [x] 3.1 エンドポイントの認証追加
  - APIエンドポイントにJWT認証を追加し、認証されたユーザーのみがアクセスできるようにします。
  - _Requirements: 1.8_

- [x] 3.2 クエリパラメータの処理
  - `date`, `base_currency`, `target_currencies` のクエリパラメータを解析し、デフォルト値を設定するロジックを実装します。
  - _Requirements: 1.1, 1.2, 1.3, 1.4_

- [x] 3.3 パラメータの入力検証
  - `date` パラメータのフォーマットが `YYYY-MM-DD` であることを検証します。
  - `base_currency` と `target_currencies` の通貨コードが有効な形式であるかを検証します。
  - _Requirements: 1.5, 1.6_

- [x] 3.4 サービス呼び出しとレスポンス形成
  - サービス層を呼び出し、取得した結果を設計書通りのJSON形式 (`{date, base_currency, rates}`) に整形して返します。
  - _Requirements: 1.9_

- [x] 4. 統合テストの拡充
- [x] 4.1 正常系シナリオのテスト
  - `date`, `base_currency`, `target_currencies` の各パラメータを組み合わせて使用し、期待通りのデータが返されることを確認する統合テストを作成します。
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.9_

- [x] 4.2 異常系シナリオのテスト
  - 認証トークンがない場合に401エラーが返ること、不正なパラメータで400エラーが返ること、データがない場合に404エラーが返ることを確認する統合テストを作成します。
  - _Requirements: 1.5, 1.6, 1.7, 1.8_
