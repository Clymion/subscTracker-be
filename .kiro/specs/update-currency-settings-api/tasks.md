## TDD実行ガイドライン

### 各サイクルの進め方
1. **Red**: 失敗するテストを書く（テストが失敗することを確認）
2. **Green**: テストを通すための最小限の実装を行う
3. **Refactor**: コードを整理し、重複を排除する

### 注意事項
- テストを書く前に実装を書かない
- 一度に一つのテストケースに集中する
- 三角測量を活用して一般化を行う
- Refactor時はテストが通る状態を維持する
