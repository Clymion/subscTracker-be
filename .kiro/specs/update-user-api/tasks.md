# Implementation Plan

## Tasks

- [ ] 1. API層での空リクエスト検証を実装する
  - PATCH /users/{userId}エンドポイントで空のJSONオブジェクト`{}`を受信した場合に400エラーを返す検証ロジックを追加する
  - リクエストボディが空、または更新対象フィールドが含まれていない場合のエラーレスポンスを定義する
  - 既存のエラーレスポンス形式（`{"error": {"code": 400, "message": ...}}`）に準拠する
  - _Requirements: 3.5, 4.2_

- [ ] 2. サービス層のユーザー名バリデーションを強化する
  - ユーザー名の長さが3文字未満または32文字超過の場合にバリデーションエラーを発生させる
  - エラーメッセージは既存のErrorMessages定数を活用または追加する
  - 既存のメール重複チェック、通貨コード検証との整合性を確認する
  - _Requirements: 1.2, 3.1_

- [ ] 3. (P) 単体テストを更新・追加する
  - UserService.update_user()のユーザー名長さバリデーションのテストケースを追加する
  - 既存の部分更新テストが新しいバリデーション条件下でも正常に動作することを確認する
  - _Requirements: 1.2, 3.1_

- [ ] 4. (P) 統合テストを更新・追加する
  - 空のJSONオブジェクト`{}`送信時に400エラーが返ることを検証するテストを追加する
  - ユーザー名長さ無効時に400エラーが返ることを検証するテストを追加する
  - 既存の成功系テスト（正常な更新）が動作することを確認する
  - 既存の空オブジェクトテスト（現在は成功を期待）を400エラー期待に更新する
  - _Requirements: 3.1, 3.5, 4.2_

- [ ] 5. 既存テストの互換性確認と修正を行う
  - 変更内容に影響を受ける既存テストケースを特定し、期待値を修正する
  - 全テストスイートを実行し、パスすることを確認する
  - _Requirements: 1.1-5.4_
